# Hollowpact production instructions

## Standing owner instruction: CONTINUE PRODUCTION

The owner repeatedly and explicitly instructs the team to keep improving this game and not stop at a milestone. This is a persistent project requirement, not a one-turn suggestion.

- Continue authorized foreground development while execution is available. Completing a build, review, version, PR or release archive is a checkpoint: immediately choose and begin the next meaningful improvement. Do not end the active production task merely to announce a milestone or offer to continue.
- Lead and coordinate agents with distinct file ownership. Use genuinely independent gameplay, visual and technical reviews. The standard is AAA studio craft and a compelling, professional monster-hunting game. Reviewers may reject it; never require praise or fabricate human enjoyment.
- Respect the latest direction: original gritty, realistic-looking monster-binding contract hunter, threatening creatures and consequential deck tactics. The former cute woodland direction is rejected. The owner grants freedom to revise any core rule when beneficial. Exercise creative judgment rather than copying inspiration lists or franchise IP.
- Preserve every old release, review finding, source/art input and ML dataset. Increment versions for major accepted milestones, freeze and verify matching builds, archive/tag them, then carry on. Protect the stable comparison baseline; repair or revert measured regressions.
- Do not substitute a scheduled trigger, a plan, a handoff or a final status message for active authorized work. An automation is only a fallback trigger; its configuration does not prove future execution. Notify meaningful progress during work and proceed into the next cycle.
- Follow honest evidence. Actual tools, sessions and access can impose hard limits; do not pretend work continues after execution has ended or claim unavailable tests/assets/accounts were used. If a real blocker prevents all useful work, identify it precisely and preserve reviewable progress. Never manufacture activity or spin unchanged checks to simulate continuous work.
- Keep temporary source freezes short and purposeful for reproducible reviews/releases. Agents must coordinate edits during a freeze and may prepare independently owned next-stage work; do not mutate frozen runtime behind a reviewer's back.
- Start from docs/CONTINUATION.md, current package/release manifests and newest independent reviews. Prioritize concrete observed shortcomings. Complete one improvement, test its effect, then repeat. Model win rate is balance evidence, not a human fun score.

These instructions govern ongoing repository work and persist across chats and context compaction. Newer explicit owner direction takes precedence. Do not treat them as permission to invent credentials, hide failures, overwrite history, spend money, or make unsupported commercial/Steam claims.
