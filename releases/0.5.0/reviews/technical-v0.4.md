Personally ran two additional production-browser storage diagnostics: a base backup plus two same-timestamp keys all remained unchanged while the exact original—including leading/trailing whitespace—was preserved under the next suffix; a primary-write quota failure after successful backup retained the original, then a later accepted action persisted a valid campaign once writes were restored. ## Additional inherited hidden-order presentation finding — 30 September 2026

**P2: grouped draw-pile display reveals relative first-occurrence order despite claiming it hides order.** `src/main.ts`'s `openDeck('draw')` fills a Map by iterating the actual draw array and renders its insertion order without sorting. This does not expose every exact next draw when copies repeat, but it does encode hidden positional information in category order. It is separate from the new consequence previews, which passed the inspected no-future-salvage/persistence boundary.

Personally reproduced in the final `da553781...` production build: natural seed-121 first battle has draw array `[sunder,scour,cairnhound,survey,ironward,scour,fenstalker]`; the dialog displays `[sunder,scour,cairnhound,survey,ironward,fenstalker]`. Reversing only the draw array in a second valid diagnostic save preserves collection/counts but changes the displayed category order to `[fenstalker,scour,ironward,survey,cairnhound,sunder]`. Both dialogs state `Grouped by card, without revealing draw order.` The reversed fixture is a diagnostic, not an earned second campaign; the first fixture is the actual reducer-created campaign state.

Report to the owner before final development preservation. Sort grouped draw entries by a stable public card ID/name independent of hidden pile order and add a focused equal-count/different-order regression in the next candidate. This inherited issue does not require deleting historical archives or imply corrupted saves. A development archive may preserve it as an explicit known limitation; polished hidden-information/quality claims remain blocked. No repair was silently applied by this reviewer.
