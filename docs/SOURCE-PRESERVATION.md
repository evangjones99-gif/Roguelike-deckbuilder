# Development source archives

The release command retains ZIP as its default. Existing versions and their source ZIPs remain unchanged. Every transaction requires matching version, exclusive lock/new destination, passing rules/build, clean committed source and matching present desktop provenance.

Future major milestones may deliberately choose `npm run release -- VERSION --source-format=bundle` after measuring both durable and temporary capacity. The official source artifact then is a version-2 Git bundle containing the exact current tree and all commit/tree/blob ancestry reachable from the pinned HEAD/production branch. It contains only those two advertised refs. Other refs, annotated tag objects, non-ancestor rejected experiments and untracked working inputs are excluded. Their retained original repository/artifacts remain necessary; this is source preservation, not a full workspace or all-ref backup.

The producer first audits canonical reviews using a temporary same-commit ZIP. That ZIP is removed after verification and is identified explicitly as temporary. The official bundle is restored into a fresh bare repository, checked with `git fsck --full --strict`, and compared against every reachable source object and every current-tree blob byte/mode/OID. Extra hidden objects, malformed/header-version/ref/prerequisite/corrupt packs fail. Review INDEX entries identify canonical bytes in the restored bundle, without claiming an official ZIP exists. Only newly generated temporary verification stores are removed; original inputs and official partial outputs are retained.

A standard restoration uses `git clone --branch codex/lanternbound-production PATH-TO-SOURCE.bundle DESTINATION`. Dependencies, generated builds, platform tools, original working-only evidence and consumer testing remain separate. A clone restores canonical Git bytes; historical text normalization can differ from raw CI evidence whose preserved archives qualify those differences.

Bundle mode validates every present desktop but does not repack Windows. Root must separately add the independently accepted original actual-tested native Windows ZIP and original evidence, preserve initial producer metadata, verify the final five archives and seal truthful source/run/platform limits. A producer-only intermediate manifest is not whole-platform acceptance.
