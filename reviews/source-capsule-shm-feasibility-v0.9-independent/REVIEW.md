## Narrow cache advice assessment — no operation executed

On Linux, POSIX_FADV_DONTNEED on a read-only descriptor advises disposal of clean page-cache pages; it does not alter file contents, size, mode, ownership, mtime or xattrs. It can be a safe narrowly scoped cache operation when the coordinator confirms no reader/writer ownership on that preserved input and its actual closed-file path/inode is frozen. It is advisory: referenced/mapped/dirty pages may remain, partial-page ranges may be ignored, and a success return does not establish cache release or cgroup charge reduction. An open existing peer reader need not corrupt bytes, but evicting its working set can harm it, so this task does not authorize active-profile/cache advice. No global drop_caches, cgroup reclaim, sync, input deletion or alias change is proposed.

For a future separately authorized operation: use the exact regular archive with O_RDONLY|O_NOFOLLOW and O_NOATIME when supported/permitted; compare descriptor fstat against the pinned path/inode/device/size/mtime, record relevant xattrs/metadata without reading its1.7GB content, give whole-file advice (0,length0), close, then measure actual cgroup current/stat and events after peers remain quiescent. Opening a descriptor and giving advice performs no content read; do not immediately rehash the entire file merely to report cache release, since that recaches it. Do not claim a fresh whole SHA from metadata stability. The later real restore must still perform the unchanged full SHA and all source proof. Safe fallback if O_NOATIME/identity/ownership fails is no advice. API semantics support byte/stat preservation, not a promised number of reclaimed bytes. No advice execution or post-advice preservation proof is supplied here.
