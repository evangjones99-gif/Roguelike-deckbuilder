## Fresh source findings

- **Generator distinction:** customHeader sets InstallDir to the exact owned generator directory under BUILD_UNINSTALLER and to the distinct installation directory otherwise. Stock installer.nsi inserts this header before its early SetOutPath and generator exit. The generator is still executed by the builder, but its directory side effect now has a separate owned destination. Smoke requires the real target absent and records the generator directory present, preserving the preexisting-target refusal. This repairs the static conflict; actual Windows compilation must prove those observations.
- **Shared registry aliases:** checkInstalledRegistry requires four distinct hive/view observations, both HKCU aliases registered at the same exact installation, and no HKLM registration. It no longer counts shared logical views as duplicate physical installs. This matches the preserved primary Microsoft shared-registry reference. Actual registry reads/install/uninstall are still unexecuted by this review.
- **Cache isolation:** the header overrides APP_INSTALLER_STORE_FILE with the exact LOCALAPPDATA-relative owned QA cache path. Stock installer.nsi inserts the header before installSection.nsh includes the installer macros and their cache copy expands. Package metadata/accepted ASAR expectations remain unchanged. Prepare records a read-only default-cache witness before packaging; smoke compares it after packaging, installation and uninstallation, and requires the owned cached installer to match the original installer hash. No post-hoc cache cleanup disguises a write. The witness covers directory/file inventory and bytes; it is not an attestation of unchanged timestamps, every filesystem metadata field or global system activity.
- **Known-folder creation:** multiUser.nsh defines KF_FLAG_CREATE before the header, but its use is inside the setInstallModePerUser macro. The header changes it to zero before initMultiUser expands that macro in both installer and generated uninstaller initialization. The final controlled /D sets the installation target. The source ordering supports suppression of this requested folder creation, but the native compiler/API behavior requires observation. No claim is made that normal build tools, NSIS temporary self-copy or Windows itself write exclusively inside the QA tree.
- **Uninstall completion:** the harness removes _?= and allows normal NSIS temporary self-copy. It does not accept launcher exit as completion: a bounded poll requires the entire unique installation directory gone, then every staged payload path absent, registry empty, and profile/staged package/sentinel/default cache/owned cached installer checks preserved. Failure inventory and failure state remain retained; there is no generic cleanup. This repairs the incomplete success oracle. Actual Windows self-copy, child completion and deletion remain gates.
- **Bounded original installer route:** the streaming helper preserves the original source, caps each numbered part at 24 MiB and the set at eight parts, records full/part hashes and sizes, and rejects empty/oversized/prior destinations. The workflow separates evidence/manifest from individually uploaded numbered parts and preserves failed or unexecuted native status. This is a plausible bounded transfer route, not evidence of any completed upload/download/reconstruction. The real installer must fit the explicit 192 MiB ceiling; otherwise the helper fails and the route needs a fresh reviewed change. Verify actual small-evidence and wrapper sizes against connector limits, every part and complete original hash before durable acceptance.

`source-ordering.json` records the exact stock expansion locations; the eight stock files already inspected for R1 are byte exact in this fresh review. The unchanged workflow restrictions still constrain repository/production branch, use fixed action commits and Node/runner settings, give contents:read only, disable persisted checkout credentials, avoid PR input and publishing, and retain diagnostics. Prepare checks the actual checkout SHA and all 29 raw runtime inputs. Strict paths, random QA identity, ancestor-link refusal, ownership/sentinel checks, no elevation helper, no process kills, no shortcuts/autorun and failure retention remain present. This review found no further activation-blocking source defect within that scope.
