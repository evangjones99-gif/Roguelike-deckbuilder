## Why QA identity is necessary

Stock NSIS reads the app GUID's prior installation location and calls `uninstallOldVersion`. Stock CHECK_APP_RUNNING can terminate same-name app processes. A unique `/D` target by itself therefore cannot protect a preexisting Hollowpact installation.

This first gate uses a cryptographically random 128-bit run token to isolate appId, GUID, executable basename, directory and user-data profile. The product remains branded Hollowpact0.7.0 with actual resource editing enabled and signing disabled. It asserts byte-identical accepted game ASAR and every installed staged file; a configuration-induced mismatch fails rather than claiming equivalent provenance. This is a QA-isolated installer mechanism, not the production appId's install/update qualification.

An exact compiled InstallDir avoids the stock installer onInit's early SetOutPath defaulting to another app directory. Stock SetOutPath creates an empty target before customInit; the generated guard therefore iterates entries and rejects anything beyond `.`/`..`, instead of incorrectly rejecting that newly created empty directory. Node preflight requires the target absent. Node ancestor checks reject links/junctions; compiled guards reject a reparse-point target, wrong owner marker, wrong directory and non-current-user/nonsilent mode. The NSIS process hook only looks for its unique executable and aborts if found; it never kills it. Installer and uninstall CLI arguments are controlled directly without a shell, with the unquoted directory override last (`/D=` and `_?=`).

Shortcuts, auto-run, elevation/elevate helper, differential updater and app-data deletion are disabled. Uninstall uses only the verified installed uninstaller's current bytes, after app closure, repeated path/marker/binary checks and a matching compiled target guard. Failure leaves installation/profile/evidence for diagnosis. The script performs no generic recursive installation cleanup and never deletes the preserved QA profile. Only the disposable newly created guard-test fixture is removed in unit tests.

## Proposed actual Windows gate

The native script checks installer/executable unsigned Authenticode status, Hollowpact/version PE resources and non-stock icon bytes. It verifies exact staged ASAR/provenance, source oracle dependencies, all staged and installed package hashes, and unique GUID absence in HKCU/HKLM32/64 before installation. It then runs actual silent per-user installation, verifies registration only in HKCU64 at the exact target, launches the actual installed executable with normal sandbox/context isolation/disabled Node integration, earns a seed121 summon and command through controls and compares full saves against exact packaged rules. It observes the shipped hunter's actual file URI/full512 source-cell draws, reloads, exports clearly synthetic negative local feedback with unchanged local storage, closes/relaunches/resumes, then runs guarded uninstall. The gate requires removal of installed EXE/ASAR/unique registration while preserving byte-exact QA profile, outside-install sentinel and staged package. Source/build/installer/executable/ASAR/package/profile hashes, exact run/ref/commit and failures are retained.

The current draft uploads the actual installer and small evidence in one artifact. A large installer artifact can exceed this connector's32MiB download limit. Before durable milestone preservation, add a reviewed bounded-part transfer route or another verified download route; the configured full artifact is not proof of durable local preservation. This gate does not auto-archive/tag/publish a release.

## Production-identity follow-up assessment

A more representative production appId case is feasible only as a separate reviewed case on a newly allocated GitHub-hosted Windows VM. It must not be offered as a workstation reproduction command. Before building or invoking anything, attest GITHUB_ACTIONS/runner environment and reject any same-GUID installation/uninstall key in both registry views/hives, same-name game processes, default user Hollowpact data/cache directories and default installed directories. Record exactly which paths/keys were examined. Mere absence of InstallLocation is insufficient: reject any matching registry key.

The compiler must retain the real appId/executable while fixing an explicit unique QA destination and profile, suppressing stock process termination, shortcuts/auto-run/elevation/app-data deletion. Add preInit absence checks before initMultiUser and stock uninstall logic, and repeat them in customInit/Node immediately before invocation. Installed registration should then point only to the verified unique target. Default production profiles remain untouched and the explicit QA profile remains outside the installation. Uninstall must verify the exact installed binary/uninstaller and current registration path, abort on mismatch and never remove defaults. The stock template performs SetOutPath before preInit and uninstaller process checking before customUnInit; any custom-template adjustment necessary to guarantee no early unintended write must be independently reviewed rather than inferred safe from a late hook. Unexpected existing state closes the case, not an invitation to remove it.

This production-identity case is not implemented or executed in this proposal. Its consumer/install/update/default-profile gaps remain open. The current isolated mechanism gate can provide concrete installer execution evidence first without endangering owner applications.
