## Result and scope

The sole new flag is `--source-format=bundle`; omit it for the existing ZIP producer. Unknown/duplicate/additional flags fail before acquiring a lock or running checks. Version validation, existing-version refusal, exclusive transaction lock, package version, mandatory npm test/build order, clean committed source, exclusive destination creation, desktop version/runtime-digest gates, streaming checksums, and retention of failed partial directories remain in place. Default archive commands, source scope, manifest fields and reviews INDEX remain unchanged for ordinary no-flag invocation. Unsupported extra arguments previously ignored are now deliberately refused by the fixed CLI contract.

Bundle mode creates a version-2 Git bundle containing exactly `HEAD` and `refs/heads/codex/lanternbound-production`, both pinned to the clean source commit. It never uses `--all`. The official bundle includes the complete current committed tree and commit/tree/blob ancestry reachable from that commit, including ancestry shared by old milestones. Other branch/tag refs, annotated tag objects, non-ancestor rejected experiments and untracked/ignored working bytes are intentionally excluded. Old versions, local refs and their bytes remain where they were. This is not a claim to preserve every filesystem input or every local tag object. Any currently tracked releases/ metadata is part of the full bundle tree; the temporary ZIP audit keeps the existing roots-excluding-releases policy.

An actual same-commit Git ZIP is generated only under a newly reserved temporary directory. The unchanged review index checks its commit comment, canonical member containment and exact Git blob identities, plus available raw/gzip lossless pairs. Its SHA256/byte size and temporary status are recorded, then it is removed. The official bundle is independently restored into a fresh bare repository, verified without prerequisites, fscked, checked for the exact advertised refs, complete reachable object closure and no extra unreachable pack objects. Current commit/tree identities and every current blob's full raw bytes, mode, SHA1 and SHA256 are compared by streamed Git reads; no checkout/text normalization is used. The official bundle gets its own streamed SHA256. INDEX and manifest honestly name the bundle and the temporary ZIP audit. New temporary verification directories are cleaned after success/failure; official partial output is retained by the unchanged release failure gate.

Every present desktop still undergoes ASAR version/source-digest checks. Bundle mode archives a matching Linux desktop but deliberately does not repack Windows. The producer stores web ZIP, source bundle and available validated Linux tar; root must separately preserve the exact accepted original native Windows ZIP and original CI evidence, verify their hashes, and finalize the five-archive receipt. The producer does not claim these additions exist or certify native quality. Default ZIP mode still performs its existing Windows repack when present. Existing six-archive milestones are untouched.

## Limits and decision

This is a bounded SHA1 Git repository/UTF-8-path implementation for the current production branch. Gitlinks/submodules are refused; symlink blobs and executable modes are byte-preserved. It needs installed Git/Python/zip/tar on the archive host, already used by this project; there is no dependency install or network operation. Output metadata calls have a 16MiB bound; blob/archive hashes stream. Windows consumers, arbitrary Git object formats/refs, source acquisition from arbitrary URLs and a durable remote full mirror were not tested or implemented.

Author recommendation: accept only after the independent R2 technical gate and root review, as a useful opt-in future preservation mode. Preserve the default producer for current v0.7. It reduces history duplication measurably but does not establish Steam readiness, native quality, graphics quality, human fun or permanent backup.

## Independent affected review and temporary-space boundary

The separate technical reviewer reports 17/17 fresh R2 affected probes passing, including version 3, hidden extra objects, malformed packs/ref headers, a standard consumer clone and actual producer-corruption failure retention. Its own attempted full-size b065 bare import then failed with `No space left on device` while concurrent archive work used /tmp. The reported initial free space was ~2.78GB; it did not independently complete that full import. Its failure/log remain in its separately owned scratch evidence. Do not call the author full-size pass an independent pass or assume free space equal to one bundle's size is a safe peak budget. The author's successful full preflight started with 6,566,150,144 temporary bytes free, and it did not measure the minimal peak/reserve threshold. Future production must verify exact durable and temporary capacity with room for Git's incoming pack/index and other concurrent writers before invoking the producer. The existing partial-output retention is tested, but it cannot guarantee an INCOMPLETE marker write when the filesystem has zero writable space.
